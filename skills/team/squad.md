# 小隊：部門主管（第 1 ↔ 2 層）與可重用的角色組

第 1 層的員工手上的事要另開人（`lead.md` §1 的判準）時，升成**部門主管**：**商討自己做**，研發、測試等從一個小隊挑、用到才開。

## 1. 小隊在哪

整台電腦共用，不屬於某個專案；不進 git，要給別台或同事就複製資料夾。外掛**不內建**小隊，由使用者指定規則產生（§3）。

```
~/.claude/office/squads/<小隊>/
├─ squad.md          ← 什麼時候用、有哪些角色、source
└─ roles/<角色>.md    ← 格式同 `roles.md` §2，layer: 2、reports_to: 部門主管
```

找卡：**專案 `roles/` 先，小隊後**——專案要特別的測試就在專案放一張同名卡蓋過去，小隊那份不動。檢查點、`collab.md` 照樣寫在專案裡。

## 2. 升部門主管、開成員、降回

1. 列 `~/.claude/office/squads/*/squad.md`，一句話提：
   > 「建議升成部門主管，用 **<小隊>**（<角色>、<角色>），先開 <角色>；預估 {粗估}。要開嗎？」

   沒有合適的小隊 → 問使用者要照什麼規則建（§3），或直接用專案卡。
2. 使用者說好：`office_profile(role=主管, team=<上層主管>)`；`collab.md`「主管」加自己一列，上層＝上層主管。告訴上層主管一句「升部門主管、用 <小隊>」。
3. **用到才開**：一次只開眼前要的角色。派工單照 `lead.md` §4，`【依據】` 要帶專案背景（必讀、範圍）——小隊卡是通用的，不知道這個專案；成員掛 `team=<你>`。
4. 成員接手：照 `roles.md` §3，卡從小隊讀，必讀只照派工單的專案背景補。
5. 你直接跟使用者商討，不經上層主管；成員回報給你，你做完一段再回報上層（`lead.md` §5 格式）。跨部門撞檔交上層主管裁定。
6. 降回第 1 層：成員都收工、佔用都放掉 → 問使用者 → 刪自己的主管列與成員的「在線」列 → `office_profile(role=員工, team=<上層主管>)`。

## 3. 建小隊（「照 <規則> 建一個 <名稱> 小隊」）

流程同 `roles.md` §1，差在三處：

- 提案表多一列「這個小隊什麼時候用」；角色只寫**跟專案無關**的職責與邊界，必讀只放規則本身（專案背景由部門主管派工時帶）。
- 部門主管自己負責商討，**不建商討卡**。
- 寫到 `~/.claude/office/squads/<小隊>/`：`roles/<角色>.md` ＋ `squad.md`：

```markdown
---
squad: <名稱>
source: <規則路徑>
---
什麼時候用：一句。
| 角色 | 一句職責 | 通常何時開 |
|---|---|---|
```

規則改版：`grep -rl "source: <規則路徑>" ~/.claude/office/squads/`，提案改哪些，使用者核可再改。
