# 角色：產生、接手、檢查點

為什麼要角色卡：session 沒有跨視窗記憶，ListAgents 名稱重開就變。卡把「這個角色做什麼、讀什麼」固定在專案裡，新 session 照卡接手。
卡在 `<office>/roles/`（`<office>` 怎麼定見 `SKILL.md`）。

## 1. 從規則產生角色（「照 <規則路徑> 設這個專案的角色」）

1. **讀規則**：只讀到分得出職責為止；大文件分段讀（Read 帶 `pages`）。
2. **在對話裡列提案表**（不寫檔）：

   | 角色 | 職責（一句） | 邊界：做／不做 | source（規則路徑＋章節） | 為什麼另開 session |
   |---|---|---|---|---|

   「為什麼另開 session」MUST 填下列其中一項（承接其他階段的主線角色填「主線」），填不出來的階段**併進別的角色**，不另外建卡——規則裡的每個階段不等於一個人（例：gstack 是一個 session 依序跑多個 skill）：

   | 判準 | 例 |
   |---|---|
   | 需要獨立觀點 | 審查、測試：做的人審自己看不出問題 |
   | 能平行做 | 不同模組、不同部門 |
   | 上下文會互相干擾 | 一邊讀大量規格、一邊寫程式 |

   規則指名「只有 X 能決定」的事（核可需求、放行發布…）是使用者或主管的權限，**不建卡**；在提案表下方列出「歸使用者／主管：…」。
3. **使用者改／核可**。🔴 建卡＝新建文件，只有使用者能核可。
4. **寫卡**（格式見 §2），一角色一檔。commit 由使用者決定。
   🔴 **主管的角色名要帶範圍：`<範圍>主管`**（例：`willy主管`、`office主管`），不能只叫「主管」。session 名稱＝角色名（§3 第 4 步），辦公室是整台電腦共用的，光叫「主管」會跟別的專案的主管撞名，下屬的 team 就分不出掛誰（jacky 2026-11-08）。
5. **建卡跟開人分開**：建完不自動開 session；要開人走 `lead.md` §1 升層。

規則改版時：`grep -l "source: <規則路徑>" roles/` 找出要重新檢查的卡，提案改哪些，使用者核可再改。

## 2. 角色卡格式

```markdown
---
role: <角色名>
source: <規則路徑>#<章節標題原文>   # 多章節同一行用「、」接：flow.md#1. 需求、#6. 發布；手動建的寫「使用者指定」
layer: 1                     # 1 或 2
reports_to: <範圍>主管        # 例 willy主管，不能只寫「主管」；只有第 1 層寫，第 2 層（小隊卡）不寫
---
## 職責
一兩句。
## 邊界
- 做：…
- 不做：…（碰到就回報主管）
## 必讀
最多 5 份，路徑＋一句為什麼。
## 可用 skill
例：/review、/qa、wiki-ingest。沒有就寫「無」。
## 交付
交什麼、交給誰、放哪。
```

- 可以多加節（例：`## 啟動位置` 在哪個資料夾／worktree 開工、`## 踩過的坑` 帶日期的教訓）；接手時照讀。

- **只放定義，不放進度**。誰持有、做到哪在 `collab.md`（主管寫）與 `checkpoints/`（持有者寫）。
- 🔴 **第 2 層（`layer: 2`）只放「怎麼做」**：職責、邊界、規則、可用工具與 skill、交付格式。不寫主管是誰（`reports_to`、「部門主管是 <名>」都不寫，主管＝開你的人）、不寫上次做了什麼或還有什麼沒做；這次做什麼由派工單帶（jacky 2026-11-08）。
- 持有者發現定義不對（必讀過時、邊界不合）→ 回報主管或使用者，不自己改。

## 3. 接手（「你是 <角色>，接手」）

捷徑：`python <外掛根>/scripts/takeover.py <角色>` 一次印出第 1～3 步要的（卡、你的名稱、撞角色、登記那行、最後一筆檢查點、collab 的主管／在線／佔用三節），不必逐檔讀；印 STOP 照第 2 步停下來問。它不寫檔，第 4 步以後照做。`<角色>` 也可以是卡上的 `office_name`（例：GUANGUAN）。

**印 MOVE（卡的啟動位置不是這裡）→ 不在這裡接**：session 開了就換不了資料夾，在這裡接讀不到那個 repo 的 `CLAUDE.md`、同名卡還可能接錯。照它的話問使用者一次要不要在那裡開新視窗，好就跑它印的 `open_role.py` 那行；開好後這個 session 不接這個角色、不登記。

1. 讀 `roles/<角色>.md`；專案沒有、派工單寫了小隊 → 照 `squad.md` §2 讀小隊的卡。都沒有 → 告訴使用者，問要不要照 §1 建；不要自己猜職責。
   - **卡在別的專案**（例如主管替別處的角色開視窗）：`python <外掛根>/scripts/roles.py <關鍵字>` 列整台電腦的卡（開過 Claude Code 的專案＋`projects.json`＋小隊；`--path <角色>` 只印路徑），不全文搜尋、不翻對話紀錄。`takeover.py` 本專案沒卡時會自動用它。找到的卡有「啟動位置」就照它開；沒寫，就用卡所在專案的根目錄。
2. `office_roster` 看有沒有**別人**已登記這個角色（職稱＝角色名）且在線 → **停下來問使用者**（`open_role.py` 開的視窗一啟動就帶這個職稱，那一列是你自己，不算）。兩個 session 不能同時頂同一角色（檢查點會交錯）。
3. 卡上有「啟動位置」→ 先到那裡（還沒建照卡上說的建）。只讀卡上的「必讀」與「踩過的坑」，再讀 `checkpoints/<角色>.md` 的**最後一筆**（第 2 層沒有檢查點，不讀）。不讀 `collab.md`——跟你有關的由主管在報到時回給你。
4. **session 名稱＝角色名**（卡上有 `office_name` 就用它）：不一樣就請使用者 `/rename`（`takeover.py` 會提醒，已有在線 session 叫這個名字會印 STOP；`open_role.py` 開的本來就是）。下屬的 `team` 記主管的 session 名稱，名稱跟著角色走，之後換人接手下屬不用重新登記；以前用舊 session 名字登記的下屬要重登一次（jacky 2026-11-08）。
   登記辦公室：`office_profile(title=<角色>, team=<主管的 session 名稱＝它的角色名>)`（`open_role.py` 開的已預先登記；名單上自己那列已對就跳過）；沒有主管（第 5 步）→ 只設 title，team 照派工單寫的，派工單也沒寫就不設。
5. 主管：**名單上自己已有 `team`（被人開出來的，開場句也會寫「開你的是 <X>」）→ 主管就是那位**，卡上寫的主管不算（jacky 2026-11-08）。沒有 `team` 才找 `collab.md`「主管」段登記、範圍涵蓋這個角色的那位（卡上的 `reports_to` 是角色名，不是 ListAgents 名稱）；沒有 `collab.md` 或沒登記主管 → 當作沒有主管，跳過報到，**不要**找名單上別的專案的主管。主管在線 → 報到（一則）：
   ```
   接手：<角色>（ListAgents=<你的名稱>）
   上次檢查點：<最後一筆的「下一步」>      ← 第 2 層改寫「等派工單」
   ```
   主管回覆跟你有關的佔用與待裁示，照它做。
6. 回報使用者三行內：接手了什麼、讀了哪些檔、第一件要做的事。

## 4. 檢查點（`checkpoints/<角色>.md`）

做到一個段落、要收工、或上下文快滿要 `/compact` 前存一筆。**只往後加，不改前面的**；只有持有這個角色的 session 寫。

```markdown
## YYYY-MM-DD HH:mm <ListAgents 名稱>      ← 當地時間
- 做完：一兩行（指 commit 或檔案路徑，不抄內容）
- 卡在：沒有寫「無」
- 下一步：接手的人第一件要做的事
```

接手只讀最後一筆。檔案長了不用清——它不進 git、只有最後一筆會被讀。

**第 2 層（`layer: 2`）不存檢查點**：每次照派工單做、交付、回報開你的人就收工；接續靠部門主管的 `collab.md` 與交付物本身（報告、commit）。外掛也不替第 2 層提醒或補寫。

外掛代勞（title＝卡名才算持有）：做了事、一小時沒存 → 下一則指令提醒一次；`/compact` 時要摘要留「做完／卡在／下一步」；正常關掉時這段沒存 → 外掛補一筆標「（自動：下線前沒存）」，只有最後指令與 `claude --resume <id>`，接手的人先 resume 讀對話末段。強制結束（關視窗、kill）補不到。

## 5. 叫人（「叫 X 來」「開 X」「找做 Y 的人」）

照順序，前一步有結果就停：

1. **在線就傳話，不開**：`office_roster` 看名牌、職稱、ListAgents 名稱有沒有對到 → `SendMessage` 轉達，或請使用者切到那個視窗。
2. **找卡**：`python <外掛根>/scripts/roles.py <關鍵字>`（使用者說的名字、職責關鍵字都試；`<外掛根>`＝這份 skill 資料夾往上兩層）。不全文搜尋、不翻對話紀錄。
3. **有卡 → 用卡上的角色名開**：`python <外掛根>/scripts/open_role.py --role <卡上的角色名> [--team <你的 session 名稱>] [--kickoff <開場檔>]`，先加 `--dry-run`。不給 `--dir` 就用卡的啟動位置；開場句會帶卡的路徑，新 session 照 §3 接手。多張卡都像 → 列給使用者選。
   **在 Claude Desktop 裡、手上有 `start_session` 工具，使用者也想在側邊欄看** → 改用它開（外掛程式叫不到它，只有模型能叫；終端機、VS Code 沒有這個工具，照上面用 `open_role.py`）：標題＝卡上的角色名（就是 session 名稱）；brief＝`你是 <角色>，接手。角色卡：<卡路徑>。開你的是 <你的 session 名稱>，它是你的主管，有事向它回報`，要交代工作再接開場檔內容。沒有預先登記，新 session 照 §3 第 4 步自己 `office_profile(title=<角色>, team=<你>)`。Desktop 會在它每輪結束時把摘要送回給你。關掉用 `archive_session`（`lead.md` §7）。
   未實測（2026-11-14）：能不能指定工作資料夾（不能的話，卡上有啟動位置的角色改用 `open_role.py`）、封存時外掛會不會補檢查點（保險起見，封存前先請它存）、每輪摘要讓你的 context 長多快。
4. **沒卡 → 問使用者**：照 §1 建卡（要核可），或這次只開一個臨時 session（`--role <名稱> --dir <資料夾>`）。不自己編職責、不用相近的名字另開一個。

開人多花的 token 是使用者的成本：使用者說了「叫／開」才開，只是「找」就先問。
`open_role.py` 會擋一層：同名或同職稱已在線 → STOP（exit 3；真要第二個加 `--force`）；名字沒卡但有相近的卡、`--dir` 跟卡的啟動位置不同 → 印 Note。看到 Note 先回第 2 步。

**開場檔**（`--kickoff`，要交代這次做什麼才寫；只是叫回來接手就不用）：內容＝`lead.md` §4 派工單，前後各加一段：
- 前：「開工先 `ToolSearch("select:SendMessage")`；`ListAgents` 沒列出自己就先傳一句『已報到』給 <你的 session 名稱>」
- 後：「做完、卡住用 SendMessage 回報，第一行一句結論；送不出去寫 `<repo 根>/peer-reply-<自己名稱>.md`、跟使用者說一聲；回報後等下一件，不自己找事做」

開好之後：告訴使用者開了誰、做什麼，提醒第一次可能卡在信任資料夾或讀 repo 外檔案的詢問，要在那個視窗按（不加 `--dangerously-skip-permissions`）。對方卡在詢問時 `ListAgents` 看不到它；回報前不催、不輪詢。
