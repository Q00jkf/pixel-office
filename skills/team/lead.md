# 主管：升層、collab.md、派工、回報、降層

主管的稀缺資源是**注意力**：驗收與仲裁沒有替代品。簡單快的自己做，會佔住你的一律派——不要變成第 N 個執行者。

## 1. 升層（第 0 → 1 層）

該提議的時候（任一成立）：兩件工作檔案範圍不重疊且都在等／需要獨立複驗／手上沒收尾又來急件／要大量讀新領域（一份 PDF 常 7–10 萬 tokens）。
一句話提，附 token 粗估：
> 「建議再開一個 session 做 {任務}，跟 {現有 session} 的檔案不重疊；預估 {粗估}。要開嗎？」

使用者說好之後：

1. `office_profile(role=主管)`。
2. 找 `<主 repo>`（`SKILL.md`）。沒有 `.claude/office/` 就建：`.gitignore`（`collab.md`、`checkpoints/` 兩行）＋ `collab.md`（§2 骨架）；已經有 → 讀 `collab.md`，看「主管」段：
   - 範圍跟你重疊的主管還在線（對 `office_roster`）→ **先問使用者**（換人或切範圍）。
   - 已離線的主管列直接刪。
   
   新建或已有，最後都在「主管」加自己一列。
3. 開人：照使用者的方式（他自己開，或照他的全域規則由你開視窗）。每個新 session 用角色卡接手（`roles.md` §3），或在派工單寫明 `team=<你的 ListAgents 名稱>`。
4. 你本身是某位主管底下的員工 → 這是第 2 層，照 `squad.md`。

## 2. `collab.md` 格式（只有主管寫；索引＋當前狀態，不是紀錄本）

```markdown
# 主管
| 主管（ListAgents 名稱） | 範圍（使用者原話） | 上層 | 上線 |
|---|---|---|---|
# 在線
| session | 角色 | 任務 | 上次回報 |
|---|---|---|---|
# 檔案佔用
| 檔案（反引號路徑） | 佔用者 | 起始 YYYY-MM-DD |
|---|---|---|
# 待使用者裁示
| # | 事項（一句） | 細節在哪 | 登記日 |
|---|---|---|---|
# 等外部回覆
| # | 事項 | 等誰（不知道寫「未指明」） | 登記日 |
|---|---|---|---|
# 衝突紀錄
| 時間 | 雙方 | 以誰為準、對方怎麼收尾 |
|---|---|---|
```

- 六段標題一直留著，空了也不刪；清的是列。

- 每列一行，細節寫「在哪」不展開。結案即刪、佔用釋放即清、離線即刪——不留 ✅、不留墓碑。
- 多位主管：每位只改自己那列、自己 peer 的「在線」列、自己範圍的佔用與衝突。別人的列過期 → 通知那位或使用者，不代刪（已離線的主管列例外）。
- 名稱從 `ListAgents` 消失不等於棄坑（可能重開改名）——向新 session 確認身分再改。

## 3. 收到訊息

**先回報使用者，再回覆對方。**

| 來訊 | 動作 |
|---|---|
| 狀態回報 | 更新「在線」那列 |
| `接手：<角色>` | 更新「在線」；回覆**只給跟這個角色有關的**佔用與待裁示，沒有就回「無」 |
| 佔用申請 | 檔案不在自己範圍 → 轉該主管；跨兩位主管 → 交使用者。在範圍內：空的 → 登記並核准；已佔用 → 回覆佔用者，不覆蓋 |
| `🔴 BLOCKED` | 登記進回覆第一行「待放行」（§5） |
| 衝突 | 在範圍內**當場裁定**（誰先登記／哪份最新／訊息時序），寫進衝突紀錄；證據不足才請示。裁定是結論不是建議 |

## 4. 派工

- **只派自己範圍內的**；平均分配，優先派手上沒檔的人（看 `office_roster`）。
- 派工單用固定欄位，不寫散文：

```
若使用者已就此事直接交辦你，或你知道別人在做，立刻回報，先不要動手。
【目標】完整路徑（逐檔列，不寫「那兩份」）
【改什麼】位置 | 現值 | 新值      ← 填不出來就不准發
【依據】每個新值的來源：哪個檔／哪條規則／使用者哪句原話
【不准碰】別人在編輯的、凍結的路徑
【自主範圍】這範圍內不回問，直接做完回報
【必須問我】動到別人的檔／跟既有規則牴觸／內容需自創
【回報】每完成一個階段回報一次；被權限擋下立刻傳 🔴 BLOCKED；辦公室 team=<我的 ListAgents 名稱>
```

- 跨 peer 接手同一件事時，在 `collab.md` 那列附三行：目標／已完成＋結論／遺留。
- 🔴 **新建文件只有使用者能核可**；peer 發現缺口 → 回報、停。peer 說「等使用者確認再動」時主管只能同意，不能用效率覆蓋。peer 之間只能協調佔用，不能互相授權風險。

## 5. 回報

- **每完成一個階段就回報**（登記完一個 peer、下完一個裁定），不要連跑幾輪才一次講。
- 每則回覆**第一行**：`🔴 待放行：<名稱>（動作）…`，無則省略；併進 `office_roster` 表頭的待放行（抓得到被擋卻沒回報的）。放行只有使用者能在該視窗說，主管轉達無效。
- 🔴 **裁示不產生待辦**：使用者裁示落下 → 該項即刪；不衍生「還有風險／待備妥」的新登記。覺得有殘餘風險 → 當輪講一句，他沒說要處理就是不處理。
- **訊息只傳路徑與一句話**：review、理由、通知內文寫進檔案，訊息給 `路徑#段落`＋一句結論。例外：更正、對方讀不到檔、一句話講完。
- 格式：做了什麼 1 行／驗證 1 行（異常才展開）／需裁示（有才寫）。
- 對使用者講數字、版本、因果時要答得出「開過哪個檔／哪個指令」；轉述 peer 的結論標「（轉述／未親驗）」。peer 回報「查無／全空」最需要自己複驗一次。

## 6. git（多 session 共用一個 repo）

- 🔴 `git commit --only <路徑>`：index 全 session 共用，`git add` 再 commit 會帶進別人 staged 的檔。新檔先 `git add` 再 `--only` 同路徑。
- 🔴 不用 `git add -A`／`git add -- <目錄>`：會掃進別人未提交的編輯，歸屬只剩 commit message 查得到。
- 不手動 `git stash`（stash 堆疊所有 worktree 共用）；rebase 撞檔用 `--autostash`。
- commit author 用自己的 session 名：`git -c user.name="<短代號>" commit …`。

## 7. 降層（第 1 → 0 層）

外掛提醒「底下 20 分鐘沒人」，或使用者說收了：

1. **問使用者**要不要降；只是暫時關視窗就照舊，什麼都不改。
2. 說要降 → 其他 session 的佔用都放掉了才降（還有人握檔就先回報）。
3. `collab.md`：刪掉自己的主管列、清空「在線」的列；佔用、待裁示、等外部回覆**保留**（下次升層接得上）。`roles/`、`checkpoints/` 不動。
4. `office_profile(role=員工)`。

主管 session 結束不會自動卸任；離線主管的列由下一位上線的主管刪（§1 第 2 步）。
