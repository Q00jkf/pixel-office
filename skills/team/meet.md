# 開會：多 session 討論出方案

前提見 `SKILL.md`「共通前提」；參與者必須在線。這份管**討論流程**，會議室畫面由 `office_meeting` 負責。

## 角色

| 角色 | 是誰 | 做什麼 |
|---|---|---|
| **主管** | 開會的 session（使用者下令開會的那個） | 出題、點名、指定輸出資料夾、發通知；**之後不參與**，只收散會通知 |
| **主持人** | 參與者名單的**第一位** | 自己也提案；整合方案、協調衝突、寫結果、通知主管 |
| **參與者** | 其餘被點名的 session（不限 team） | 只從**自己的職責**提案、確認自己那一段 |

## 🔴 規則（每個角色都適用）

| 規則 | 為什麼 |
|---|---|
| **只寫自己的檔**：提案寫 `提案-<名牌>.md`；只有主持人寫 `方案草稿.md` 與最終 `方案.md` | 多 session 改同一檔沒有鎖，後存檔無聲覆蓋先存檔 |
| **只寫自己職責的部分**，不評論、不改寫別人的領域 | 省 token、內容不重複；整合是主持人的事 |
| **訊息只傳路徑與一句話**，不把內容貼進訊息 → 通則與例外見 `lead.md` §5 | 同一份內容不在訊息與檔案各出現一次 |
| **不讀別人的提案**（主持人除外） | 讀 N×N 份變成主持人讀 N 份 |
| **討論期間不聯絡主管**；唯一例外：被權限擋住 | 主管開完會就不參與 |
| **不代做被擋的動作**：自己寫不了輸出資料夾 → 在自己視窗回報使用者，並告訴主持人「我缺席」 | 權限是各 session 分開的，代做＝繞過使用者的決定 |
| **不設期限**：討論出結果就散會；何時收斂、要不要再協調由**主持人決定** | 結果比時間重要；主持人看得到全貌 |
| 主持人**決定不了**的分歧才找主管裁示 | 主管開完會就不參與，只處理卡住的決定 |

開會由使用者下令＝核可在**輸出資料夾**內建這次會議的檔；資料夾以外不建新文件（`lead.md` §4：新建文件只有使用者能核可）。

## 主管：開會

使用者說「開會討論 X，找 A、B、C，結果放 Y」→ 缺哪項就問（題目、參與者、輸出資料夾三項必填；不設期限）。

1. **核對參與者在線**：`ListAgents`；不在名單的告訴使用者，不要硬送。名單第一位＝主持人。
2. **定職責**：每位參與者一句話職責。來源依序：使用者指定 → 角色卡的「職責」→ `office_roster` 的職稱 → 問使用者。
3. **建會議資料夾** `<輸出資料夾>/<YYYY-MM-DD>-<題目短名>/`，寫 `議題.md`（格式見下）。
4. **發開會通知**給每位參與者（一則一人，用他的 ListAgents 名稱）：

   ```
   📋 開會：<題目>｜你的職責：<職責>｜主持人：<名牌>
   議題：<議題.md 路徑>（讀 skill pixel-office:team 的 meet.md，照「參與者」段做）
   ```

5. **畫面**：`office_meeting(action="start", topic=<題目>, participants=[<各參與者 ListAgents 名稱>])`（不帶 minutes：參與者都離線或散會時才清空會議室）。
6. 回報使用者「已開會：參與者、主持人、資料夾」，**到此結束**。之後只會收到兩種訊息：
   - `散會：…` → 轉告使用者。
   - `請裁示：…` → 主管能依既有裁示／權責決定就直接回主持人；涉及新決策就問使用者，再把答覆回給主持人。**只回答被問的那一點**，不重開討論。

## 參與者：收到 `📋 開會`

1. 讀 `議題.md`（只讀這份；職責需要的資料自己查，**不讀其他人的提案**）。
2. 在會議資料夾寫 `提案-<你的名牌>.md`（格式見下，**15 行內**）。
3. `SendMessage` 給主持人：`提案好了：<路徑>`。
4. 等主持人來訊：
   - `請確認：<方案草稿 路徑>#<你那段>` → 只讀你那段；同意回 `同意`，不同意回一行「要改什麼＋理由」。
   - `協調：<問題>，對象 <名牌>` → **直接**和對方談（`SendMessage` 給他），談定後兩人各自在自己的提案檔補一行「協調結果」，再回主持人 `協調好了`。

## 主持人（＝第一位參與者）

1. 先照「參與者」1～2 寫自己的提案。
2. 等所有人的 `提案好了`；有人遲遲沒交 → `ListAgents` 確認他還在線，不在就以已交的整合、方案標「缺席」。
3. 讀所有提案，寫 `方案草稿.md`（格式見下）：每人一段（照他的職責），加「整合」與「需要配合」。
4. **有衝突**（兩人建議互相牴觸，或某人需要另一人配合但對方沒提）→ 只找相關的兩人：
   `協調：<一句話問題>，對象 <對方名牌>`；等兩人都回 `協調好了`，讀他們補的那一行改草稿。
   要不要再協調由你判斷；你能依議題的目標與限制取捨就**直接決定**並在方案寫明理由。
   **決定不了**（兩案都合理、取捨超出議題給的範圍）→ `SendMessage` 給主管：
   `請裁示：<一句話問題>｜A：<名牌> 主張…｜B：<名牌> 主張…｜詳見 <方案草稿 路徑>#<段落>`，等回覆後照裁示改。
5. 對每位參與者送 `請確認：<路徑>#<他那段>`；收齊回覆、照「要改什麼」修正。
6. 你判斷已經有結果 → 寫最終 `<輸出資料夾>/<會議資料夾>/方案.md`（草稿定稿）。
7. 散會：
   - `SendMessage` 給主管：`散會：<題目> → <方案.md 路徑>`
   - `office_meeting(action="end")`
   - 對每位參與者送 `散會`。

## 檔案格式

**`議題.md`**（主管寫）

```markdown
# <題目>
- 主管：<名牌> ｜ 主持人：<名牌> ｜ 開會：<YYYY-MM-DD HH:MM>
- 輸出：<方案.md 的完整路徑>

## 背景與限制
<主管給的前提、不能動的東西、要回答的問題；3～8 行>

## 參與者
| 名牌 | ListAgents | 職責 |
|---|---|---|
```

**`提案-<名牌>.md`**（每位參與者，15 行內）

```markdown
## <名牌>（<職責>）
- 建議：（3～5 點，只講自己的領域）
- 需要誰配合：（名牌：要什麼；沒有寫「無」）
- 風險：（1～2 點）
```

**`方案草稿.md` → `方案.md`**（主持人）

```markdown
# <題目>：方案
- 參與：<名牌（職責）…> ｜ 缺席：<…或無> ｜ 日期：<YYYY-MM-DD>

## 各職責
### <名牌>（<職責>）
<整理自他的提案，3～5 點>

## 整合
<各段怎麼接起來：順序、誰先誰後、交界的決定>

## 需要配合
| 誰 | 對誰 | 要什麼 |
|---|---|---|

## 決定紀錄
<協調或裁示過的點：誰主張什麼、怎麼定的、誰定的（主持人／主管）；沒有寫「無」>
```
