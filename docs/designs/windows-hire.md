# Design: Windows 上開人（招聘、交接、叫角色）＋手機的叫角色、團隊、關係圖

2026-11-26，office設計
Status: 核可（jacky 2026-11-26，見文末「定案」）
基準：0.63.62

## 問題

1. **Windows 上手機開不了人**：招聘、Codex 招聘、交接換主管、自動多開幫手，全部靠 tmux（`remote/hr.ts` `hire()` 第一行就是「沒有 tmux 就回失敗」），Windows 沒有 tmux。
   2026-11-26 在 Windows 實測手機頁：其他人事功能（聊天、換模型、壓縮、清空、解雇、調部門、協作桌、會議、排班）都能用，只有這一串不行。
2. **手機沒有「叫角色」**：電腦上的關聯圖（`team_window.py --relations`）能從角色卡叫人、從主管卡開專案、右鍵關 session；手機只能「招聘」一個沒有角色卡的新人。
3. **手機沒有關係圖**：手機看得到辦公室與協作桌，看不到「誰在誰底下」的樹。

## 現況：開人的幾條路

| 從哪裡開 | 怎麼開 | Mac／Linux | Windows |
|---|---|---|---|
| 手機「招聘」 | `hr.ts` `hire()` → `tmux new-session … claude --session-id <sid> …` | ✅ | ❌ 沒有 tmux |
| 手機交接、幫手、Codex | 都經 `hire()`／`hireCodex()`，之後用 tmux 抓畫面、打字 | ✅ | ❌ |
| 關聯圖叫角色 | `team_window.py` `summon_role()` → `add_tab()`；`--relations` 版呼叫 `open_role.py` | — | ✅ |
| skill 叫人（`roles.md` §5） | `open_role.py`：預先登記 `presets/<sid>.json`、PowerShell 新視窗跑 claude | dry-run | ✅ |

tmux 除了「開」，還負責三件事：

| 用途 | 用在哪 | Windows 現況 |
|---|---|---|
| 抓畫面 | 新人卡在確認畫面（信任資料夾等）→ 手機卡片列選項（`stuckOptions`、`pressStuck`） | 沒有 |
| 打字 | 外掛沒回應時，用 tmux 打 `/model`、`/compact`、`/clear`（`typeLine`） | 外掛在線時本來就走外掛（`hrAsk`），實測可用；外掛不在線才需要 |
| 認得自己開的 | Codex 交給 App／接回、`launchState`、`reapOwn` | 沒有 |

## 限制

- **不能動 Mac／Linux 的行為**（jacky 2026-11-26）：tmux 那條路原樣保留，Windows 另走一條。
- **開對話一律開成獨立視窗**（全域規則，jacky 2026-11-26）：Windows 上用 `open_role.py`，一個對話一個視窗；不用 Desktop session、不用 `start_session`。
- bun 沒有內建的虛擬終端（pty）；Windows 上要有「抓得到畫面」的終端，得靠 Python 的 pywinpty（團隊視窗已在用）。
- 伺服器在背景跑；從背景程序開出看得見的視窗，Windows 上**要實測**（見「待實測」）。
- 手機開人＝遠端在電腦上跑程式：沿用現有的門檻（JWT／本機金鑰、`access-log.jsonl` 每次都記、手機招的預設 auto、本機呼叫預設手動）。

## 做法比較（Windows 的開人）

| | A. 開成獨立視窗（`open_role.py`） | B. 開進團隊視窗的分頁 | C. 背景 pty 程序（看不到視窗） |
|---|---|---|---|
| 怎麼開 | 伺服器呼叫 `open_role.py`（要補參數） | 伺服器請團隊視窗 `add_tab`（要新增本機控制介面） | 每位新人一支 Python 程序抱著 pywinpty |
| 電腦上看得到 | ✅ 一個人一個視窗 | ✅ 一個人一個分頁 | ❌ 只能從手機看 |
| 卡在確認畫面 | ❌ 抓不到畫面，只能偵測「開了但遲遲沒進辦公室」 | ✅ 分頁的畫面就在團隊視窗手上 | ✅ |
| 打字（外掛沒回應時） | ❌ | ✅ | ✅ |
| 前提 | 無 | 團隊視窗要開著 | 無 |
| 跟全域規則 | 一致 | 不一致（規則說獨立視窗；分頁只用在實測） | 不一致 |
| 工作量 | 小：`open_role.py` 加參數，`hr.ts` 加 Windows 分支 | 中：團隊視窗加控制介面（金鑰、只聽本機），`hr.ts` 接上 | 大，又看不到視窗 |

**建議 A**。理由：跟全域規則一致、工作量小，關聯圖本來就這樣開，不必另外維護一條路。抓不到畫面的代價用「偵測＋叫你到電腦按」補（見下）；之後真的常卡，再加 B 當第二期。

## 提案（A）

### 1. 一支開人程式：`open_role.py` 補參數

手機招聘、交接、幫手、叫角色在 Windows 上都改成呼叫 `open_role.py`，不另寫一套。要補的參數：

| 參數 | 為什麼 |
|---|---|
| `--session-id <uuid>` | 伺服器要先知道新人的編號，才能預先登記、追蹤、交接（現在由 `open_role.py` 自己產生） |
| `--model`、`--permission-mode`／`--effort` | 招聘選的智力等級、模式（對應 `claudeModeArgs`） |
| `--add-dir`（可多個） | 坐協作桌的人要讀寫桌子的資料夾（`addDirArgs`） |
| `--task-file <檔>` | 招聘時交代的工作。用檔案，不放命令列（中文、長度、引號） |
| `--role-type manager`、`--name-only` | 預先登記主管身分；沒卡的新人只給名字，不找卡 |
| `--json` | 回 `{"sid","pid"}` 給伺服器，不印人看的字 |

`hire()` 的 Windows 分支：組參數 → `python -I open_role.py … --json` → 拿到 sid 照原本流程（`ctlSet`、回「大約十幾秒後進辦公室」）。Mac／Linux 不變。

### 2. 卡住怎麼辦（沒有畫面可抓）

- **開之前先擋最常見的卡點**：資料夾沒被信任過（`~/.claude.json` 的 `projects.<dir>.hasTrustDialogAccepted`）→ 手機先說「這個資料夾第一次用，開了會停在信任詢問，要到電腦按」，再讓你決定開不開。只讀那個欄位，不替你改。
- **開了之後**：90 秒內沒進辦公室（名冊沒有這個 sid）→ 手機卡片寫「<名字> 開了但還沒進辦公室，可能停在確認畫面，請到電腦看標題是 <名字> 的視窗」。不給選項按鈕。
- 電腦上叫出那個視窗：沿用 `focus_window.py` 的做法（伺服器端不新增）。

### 3. 交接、幫手、Codex 在 Windows

| 功能 | 做法 |
|---|---|
| 交接換主管（`handover.ts`） | 新人用 1. 開；「等新人真的接手」本來就看名冊，不必改（2026-11-26 實作查到，原本這格寫「看 tmux」是設計寫錯） |
| 自動多開幫手 | 同 1.；收掉幫手用現有的解雇（`procOf`＋結束程序，0.63.61 已修好） |
| Codex 招聘／交給 App／接回 | **這一期不做**：Codex 那一套（`codexToTmux`、`launchOwner`、鎖）跟 tmux 綁得最深。Windows 手機上照舊灰掉，寫明原因 |

### 4. 手機「叫角色」「開專案」（團隊）

把關聯圖已經有的判斷搬成共用的，手機與團隊視窗讀同一份：

- **抽出共用模組**：`team_window.py` 的 `roster_cards`、`manager_projects`、`launch_options` 移到 `scripts/cards.py`，加 `--json` 命令列。團隊視窗改成 import 它，行為不變。
- **伺服器新增兩個唯讀端點**：`/cards.json?id=<被點的人>`（那人所在專案的第 1 層卡＋小隊）、`/projects.json`（有主管卡的專案）。都只回卡名、職稱、說明，不回卡的全文與路徑。
- **伺服器新增 `/summon`**：只收「上面清單裡出現過的卡」的代號，不收路徑（防止手機頁送任意檔名）。在線就不開、回「已在線，改傳話」（同 `open_role.py` 的 STOP）。
  - Windows → `open_role.py`；Mac／Linux → `hire()` 帶「你是 <角色>，接手。角色卡：…」開場句。
- **手機頁**：
  - 點人 → 人事 → 新增「叫他的團隊成員」：列卡，點了就開，掛在被點的人底下。
  - 辦公室空白處 → 新增「開專案」：列專案的主管卡。
- **門檻**：同招聘（`hirePerm`：手機預設 auto；本機呼叫預設手動），每次寫 `access-log.jsonl`。

### 5. 手機關係圖

- 純畫面：用 `state.json` 已有的 `role`、`team`、`agent` 畫樹（主管 → 部門主管 → 員工），不加新資料。
- 放在手機頁底部新增一個「關係」分頁，跟辦公室並列。點節點＝開那人的人事選單（跟點辦公室裡的人一樣），長按空白＝「開專案」。
- 畫法參考團隊視窗 `web/index.html` 的關係圖，**不共用程式**（那邊是桌面滑鼠操作、這邊是手機觸控；硬共用兩邊都難改）。

### 6. 關掉 session

手機已經有「解雇」，等同關聯圖右鍵的「關掉」。待你決定：要不要在選單上另外加一個「關掉（之後可以 `--resume` 回來）」，跟「解雇（離開辦公室）」分開。

### 7. 順便：手機核准被擋時講清楚原因

2026-11-26 查到：這台電腦有組織強制開啟的內建 plugin `cc-plugin-sec-default`，排在前面、跳過 pixel-office 的權限掛點，手機核准的單永遠送不出去。
提案：外掛偵測到自己的 `classic.PermissionRequest` 沒被呼叫（有人 `waiting`，卻沒有對應的單），手機卡寫「這台電腦的安全設定擋住了外掛的權限掛點，請到電腦按」，不讓人以為只是手機頁沒開。**怎麼可靠地偵測，還要再看**：Claude Code 跳過時會在對話紀錄寫一行 `informational`，可能可以讀。

## 待實測（第 1 期動工前先驗）

1. 背景跑的伺服器（bun）呼叫 `open_role.py`，視窗會不會出現在桌面上。伺服器若是被系統服務那類程序帶起來的，開出的視窗可能看不見。看不見的話，改成由團隊視窗或一支常駐的小程式代開。
2. `~/.claude.json` 的資料夾信任欄位，在目前的 Claude Code 版本還是不是這個名字。

## 定案（jacky 2026-11-26）

- 做法 **A**（獨立視窗，`open_role.py`）。
- 這一輪做 **第 1～4 期**，加上：6.「關掉」與「解雇」分成兩個按鈕、7. 核准被擋時講清楚原因、`roles.md` §5 拿掉 `start_session` 那段（跟全域規則一致）。
- Codex 在 Windows、做法 B 不在這一輪。
- **新增的畫面保持現在的美術風格**：沿用 `remote/v2/scene.css` 的顏色變數、字體、圓角、底部選單（sheet）與卡片的樣式；關係圖的節點用辦公室裡已有的人物頭像與名牌樣式，不引入新的配色或 UI 套件。

## 驗收準則（測試逐條驗，每條過／不過附證據）

Mac／Linux：
- M1 這一輪動到的檔，原本的測試全部照舊通過（`claude plugin test .`；`bun test remote/<動到的>.spec.ts` 逐檔跑）。
- M2 `hire()`、`handover.ts`、幫手在非 Windows 走的仍是 tmux（看程式分支＋原有測試）。

Windows（實機，測試用伺服器 `PO_DEV=1 PO_PORT=8782`）：
- W1 手機頁招聘一位 Claude：出現一個新視窗、標題是名字，90 秒內進辦公室，名牌、職稱、主管照招聘時選的。
- W2 招聘到從沒信任過的資料夾：開之前先提示要到電腦按；開了 90 秒沒進辦公室，手機卡片寫明「可能停在確認畫面」。
- W3 交接換主管：新人開成視窗、上線後桌子換主管，舊主管照原本流程處理。
- W4 自動多開幫手：答應後開出幫手視窗；收掉幫手會結束那個視窗的程序。
- W5 手機「叫他的團隊成員」：只列那人專案的卡＋小隊；點了開出視窗、掛在被點的人底下；已在線的回「改傳話」不重開；送清單外的卡代號回錯誤。
- W6 手機「開專案」：列有主管卡的專案，點了開出主管視窗。
- W7 手機「關係」分頁：樹的上下關係跟 `office_roster` 一致；點節點開人事選單。
- W8 「關掉」：程序結束、之後 `claude --resume <id>` 接得回對話；「解雇」行為不變。
- W9 核准被擋：有人等允許、外掛的權限掛點被跳過時，手機卡寫明是電腦的安全設定擋住。
- W10 Codex 招聘在 Windows 照舊灰掉並寫明原因。
- W11 新畫面的美術：跟現有手機頁並排截圖比對，顏色、字體、按鈕、選單樣式一致（附截圖）。
- W12 `open_role.py` 原本的用法（關聯圖叫人、skill 叫人）照舊可用（`--dry-run` 輸出比對＋實際開一次）。
